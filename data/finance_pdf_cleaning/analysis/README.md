# 財報特徵工程管線

把 `processed/` 下各園各年度的財報 CSV 彙整成統一長表，並計算 YoY、Z-score 與跨表衍生指標，供後續風險評分使用。

## 資料年份限制（重要）

| 資料類別 | 涵蓋年份 | 說明 |
| --- | --- | --- |
| 收支餘絀表（收支類）| 109～113 | 109 由 110 學年度 PDF 第 7 頁（前一年度欄）抽出 |
| 其他所有表（非收支類）| 110～113 | 資產負債、現金流量、附表二/三/四等皆無 109 |

## 執行順序

```bash
# 0)（選用）抽取營運資料（招收人數、員工數、教保員數），彙整成 operating_long.csv
python data/finance_pdf_cleaning/scripts/extract_financial_reports.py --operating-only --school-year 113 --kindergarten N01
# 1) 彙整所有財報 CSV 成統一長表
python data/finance_pdf_cleaning/analysis/build_long_table.py
# 2) 計算特徵（YoY / Z-score / 衍生指標）；若 operating_long.csv 存在會自動算每生支出、師生比
python data/finance_pdf_cleaning/analysis/build_features.py
```

## 營運資料 (operating_long.csv)

由財報第 10 頁「一般概況」抽出，指標包含：核定招收人數、實際招收人數、學生人數
（=實際招收人數）、員工人數、教保人員數。僅有 110～113（非收支類），109 無資料。
`build_features.py` 偵測到此檔會自動 `outer merge`，計算每生人事費、每生支出、師生比；
109 年因無營運資料，這些衍生指標為 `NaN`（不補 0）。

輸出於 `analysis/outputs/`：

- `metric_long.csv`：統一長表（園代碼, 園名, 學年度, 資料表, 指標, 數值, 資料類別）
- `features_long.csv`：長表加上 YoY 變化額/率、歷史均值/標準差、近 3 年移動平均、Z-score
- `features_derived.csv`：跨表衍生指標寬表（每生人事費、每生支出、師生比等）

## 三條防呆規則（已落實於 build_features.py）

1. **YoY 基準**：收支類 110 年以 109 為基準可算；非收支類最早年（110）的 YoY 一律 `NaN`，趨勢自 111 起算。
2. **跨表衍生指標**：以 `how='outer'` 合併營運資料，缺營運資料的年度（如 109）衍生指標為 `NaN`，**絕不補 0**。
3. **歷史基準比對**：動態時間窗——收支類歷史可含 109，非收支類僅自 110 起算；`expanding`/`rolling` 皆設 `min_periods`，年份不足不報錯。

## 可擴充性（新增資料源不需重做）

下游只依賴 `metric_long.csv`。要新增資料源（學生人數、教保人員數、營運與人事事件等），
只需另外產生一份**相同欄位的長表**，下游即自動融合：

- 財務類新指標：直接讓 `build_long_table.py` 多一個 loader，append 進 `metric_long.csv`。
- 營運資料：另存為 `analysis/outputs/operating_long.csv`（欄位含 `園代碼, 學年度, 指標, 數值`，
  指標如 `學生人數`、`教保人員數`）。`build_features.py` 偵測到該檔會自動 `outer merge`，
  並計算每生支出、師生比等衍生指標；沒有該檔時這些欄位保持 `NaN`，不影響財務特徵。

# 法遵風險預警評分引擎 (risk_scoring_engine.py)

不以單一財務指標判定違規，而是透過三種比較維度辨識高風險機構，作為人工查核的優先排序依據。

## 執行

```bash
# 用內建 dummy data 跑示範（三所模擬幼兒園 109~113）
python data/finance_pdf_cleaning/analysis/risk_scoring_engine.py

# 用真實資料跑（讀 metric_long.csv + operating_long.csv，輸出 risk_scores.csv）
python data/finance_pdf_cleaning/analysis/run_real_scoring.py
```

## 四階段模組（OOP）

| 階段 | 類別 | 職責 |
| --- | --- | --- |
| Stage 1 | `FinancialFeatureEngineer` | 財務異常特徵：年度變化、預決算、費用結構、每生指標、跨表勾稽 |
| Stage 2 | `OperationalFeatureEngineer` | 營運異常特徵：師生比、教職員流動率、加班費負荷 |
| Stage 3 | `EventDataIntegrator` | 事件資料整合接口：管教回報、負評、裁罰（`register_*` + `merge`） |
| Stage 4 | `KindergartenRiskScoringEngine` | 交叉驗證評分：三維度比較、燈號分級、法遵風險指數 |

## 三種比較維度

1. **歷年自我比較 (Self-Historical)**：以該園「當年之前」的歷史為基準算 z-score，突發變化才會高分（避免當年值稀釋自身偏離）。
2. **同業相對比較 (Peer-Relative)**：同縣市 + 同規模帶（每 20 人一帶）+ 同年份群體 z-score；群體樣本不足時自動退回較粗分組（同縣市 → 全體同年）。
3. **事件前後比較 (Pre/Post-Event)**：給定事件年份（如 113），自動回溯事件前 1~2 年（111-112）哪些指標已達 RED/YELLOW，用於事前預警檢視。

## 嚴重程度分級（文字＋數字，不用顏色符號）

| 等級 | 分數 | 意義 | 觸發條件 |
| --- | --- | --- | --- |
| `RED` | 3 | 高度異常 | 任一維度偏離度 \|z\| ≥ 2.0 |
| `YELLOW` | 2 | 中度異常 | 任一維度偏離度 \|z\| ≥ 1.0 |
| `GREEN` | 1 | 正常 | 未達門檻 |
| `N/A` | 0 | 資料不足 | 該指標無資料或歷史點數不足 |

整體 **法遵風險指數**（0~100）＝ 各指標等級點數 × 面向權重加總後正規化。面向權重：財務 1.0、營運 1.2、事件 2.0。
整體風險等級：`高風險`（指數 ≥50）、`中風險`（≥25）、`低風險`（<25）。

## Stage 1 財務異常特徵一覧

1. **年度變化異常**
   - `{科目}_YoY`：年增率 =（本年決算 − 前年決算）/ |前年決算|
   - `{科目}_連續成長年數`：連續正成長的年數（偵測連續微幅成長 vs 突然暴增）
   - `{科目}_波動度`：該科目 110~113 標準差 / 平均
2. **預決算異常**
   - `{科目}_執行率` = 決算 / 預算
   - `{科目}_偏離率` =（決算 − 預算）/ 預算
   - `預算超支科目比例` = 超支科目數 / 有預決算的科目數
3. **費用結構異常**
   - `{科目}_占比` = 該科目決算 / 支出合計
   - `{科目}_占比變化`：占比逐年差異（標記占比突然改變的科目）
4. **規模標準化（每生）指標**
   - `每生人事費`、`每生食材費`、`每生總支出`、`每生業務費`、`每生修繕費`
   - `每生每日餐食成本`（若有供餐天數）
5. **跨表勾稽與其他財務指標**
   - `收入成長率`、`支出成長率`、`收支成長率差`、`收支餘絀率`
   - `流動比率` = 流動資產 / 流動負債
   - `負債比率` = 負債總額 / 資產總計
   - `現金流異常`：本期稅後餘絀 > 0 但期末現金淨增加 < 0（帳面盈餘卻現金流出）
   - `scan_notes_keywords()`：財務報表附註 NLP 關鍵字檢索接口（如：補助、專案、重大支出）

（費用科目：人事費、業務費、材料費、食材費、維護費、修繕購置費、業務發展費、其他支出）

## Stage 2 營運異常特徵一覧

- `師生比` = 學生人數 / 教保人員數；`師生比惡化幅度`：逐年變化
- `教職員流動率` = 離職人數 / 員工人數；`流動率變化`：與歷年比較
- `加班費負荷` = 加班費 / 總人事費；`加班費負荷變化`

## Stage 3 事件資料接口

以 `register_reports / register_reviews / register_penalties / register_source` 掛入含
`幼兒園ID, 年份` 的事件表，`merge()` 以 `how='left'` 併回，缺資料為 `NaN`（不強制補 0）：

- 不當管教/體罰/打罵類回報數量
- 負面評論比例
- 官方違規/裁罰次數

| 指標 | 怎麼解讀（越危險代表什麼） | 需要的來源欄位 | 目前是否有資料 |
| --- | --- | --- | --- |

| **教職員流動率** | 離職比例高代表人力不穩、管理或勞動條件問題，常與照顧品質下降相關 | **離職人數**、員工人數 | ⛔ 財報無離職人數 |

## 最終輸出 (risk_scores.csv)

每列一個（幼兒園ID, 年份），欄位包含：

- 各項特徵值（每生人事費、師生比…）
- 每個核心指標的三種比較：`{指標}_歷年z`、`{指標}_同業z`、`{指標}_等級`（RED/YELLOW/GREEN/N/A）、`{指標}_等級分數`（3/2/1/0）
- `法遵風險指數`（0~100）、`整體風險等級`（高/中/低風險）
- 若指定事件年份：`事件前預警`（列出事件前已異常的指標）、`事件年份`

## 為什麼有些指標的等級分數是 0（N/A）

風險等級分數對應：`RED=3`、`YELLOW=2`、`GREEN=1`、`N/A=0`。
其中 **`N/A(0)` 代表「該指標沒有輸入資料，無法判定」，不是「正常」也不是「零風險」**。
引擎在遇到來源欄位不存在時，刻意給 `N/A(0)` 而不猜測，避免資料缺口被誤讀成安全。

目前用純財報資料跑，以下三個指標會固定是 `N/A(0)`，因為財報 PDF 本身沒有這些數字：

| 指標 | 為什麼是 N/A(0) | 如何補齊 |
| --- | --- | --- |
| **教職員流動率** | 財報只寫年度末員工/教保人數，**沒有逐年離職人數** | 提供人事異動名冊（含 `幼兒園ID, 年份, 離職人數`）；或以員工人數逐年變化近似 |
| **加班費負荷** | 收支餘絀表的人事費是總額，**未拆出加班費** | 從附表二/三的「加班費」子項補抽成獨立欄位（財報內就有，可行） |
| **不當管教事件** | 屬外部事件資料，**財報完全沒有** | 接 `kindergarten-intelligence`（家長回報、Google 評論、政府裁罰）產出，用 Stage 3 的 `register_*` 掛入 |

補齊後，`build_long_table.py` / `operating_long.csv` 或 Stage 3 事件表提供對應欄位，
引擎會**自動**把這些指標從 `N/A(0)` 變成實際等級，不需改動評分邏輯。
